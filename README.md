# PCB Anomaly Detection

![tests](https://github.com/sadramajidi04/pcb-anomaly-detection/actions/workflows/ci.yml/badge.svg)

Unsupervised visual inspection of printed circuit boards. Models are trained on
**defect-free images only** and flag defects with a localisation heatmap.

| Input | Output |
|---|---|
| a board photo | anomaly score, defect / normal verdict, heatmap overlay |

## Why this problem
On real production lines defective boards are rare and defect types keep
changing, so a supervised detector (e.g. YOLO) has little to learn from.
Anomaly detection only needs *normal* boards, which are abundant.

## Approach
Two models are compared on the same data and metrics:

- **Baseline: convolutional autoencoder.** Learns to reconstruct good boards;
  large reconstruction error = anomaly.
- **Main model: PatchCore** (Roth et al., CVPR 2022). A frozen ImageNet
  Wide-ResNet50 turns each image into patch features; the patches of all good
  images form a memory bank (reduced with greedy k-center coreset sampling).
  A test patch's anomaly score is its distance to the nearest bank entry.
  There is no gradient training, so very few good images are needed.

## Quick start
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && pip install -e .
pytest
```

**Data:** the four PCB categories (`pcb1`..`pcb4`) of the VisA dataset
(Zou et al., ECCV 2022; licence CC BY-NC-SA 4.0, i.e. non-commercial use).
```bash
wget https://amazon-visual-anomaly.s3.us-west-2.amazonaws.com/VisA_20220922.tar
mkdir -p data/VisA && tar -xf VisA_20220922.tar -C data/VisA   # check data/VisA/pcb1/Data exists
git clone https://github.com/amazon-science/spot-diff.git
python spot-diff/utils/prepare_data.py --split-type 1cls --data-folder data/VisA \
    --save-folder data/VisA_pytorch --split-file spot-diff/split_csv/1cls.csv
```
The category folder is then `data/VisA_pytorch/1cls/pcb1` (layout
`train/good`, `test/good`, `test/bad`, `ground_truth/bad`; any MVTec-style layout works).

**Run everything** (train both models, evaluate, stress-test, fill the tables below):
```bash
bash scripts/run_all.sh data/VisA_pytorch/1cls/pcb1
```
or step by step:
```bash
python scripts/train_autoencoder.py --root data/VisA_pytorch/1cls/pcb1
python scripts/train_patchcore.py   --root data/VisA_pytorch/1cls/pcb1   # add --backbone resnet18 --coreset-ratio 0.01 for CPU
python scripts/evaluate.py          --root data/VisA_pytorch/1cls/pcb1
python scripts/robustness.py        --root data/VisA_pytorch/1cls/pcb1 --model patchcore
python app.py --model patchcore                                           # needs requirements-demo.txt
```

## Design decisions
- **VisA instead of MVTec AD.** MVTec AD has no PCB category; VisA provides four
  PCB sets with pixel-level masks.
- **Unsupervised, not YOLO.** Matches the data reality of a factory (few defects).
  A supervised detector would need labelled defects of every type.
- **Autoencoder as baseline, PatchCore as main model.** Autoencoders can learn an
  "identity shortcut" and reconstruct defects too well. Having both makes the
  improvement measurable instead of assumed.
- **256x256 input, layer2+layer3 features.** Layer2 keeps spatial detail, layer3 adds
  context; this is the standard PatchCore trade-off between locality and semantics.
- **Coreset subsampling (10% default).** Cuts memory and inference time at a
  small accuracy cost; the ratio is a CLI flag.
- **Metric code is model-agnostic and torch-free.** `evaluate_model` takes any
  `predict(images) -> (scores, maps)`, so metrics, robustness and the demo logic
  are unit-tested without a GPU.
- **Honest thresholding.** The best-F1 threshold is picked on test data and labelled as such.

## What went wrong along the way
- MVTec AD, my first dataset idea, contains no PCBs.
- Gaussian smoothing with reflect padding crashed on very small inputs (pad must be
  smaller than the map); the kernel is now truncated and a test covers it.
- Greedy coreset selection could re-pick duplicate points when the data had identical
  patches (constant images); selected points are now masked out and a test covers it.
- Several early test expectations were simply wrong (e.g. a hand-computed AUROC);
  writing metric tests first caught that before it could contaminate results.

## Limitations
- Images are downscaled to 256x256; **small defects can vanish** at this resolution.
  Higher `--image-size` helps but costs time and memory.
- One model per board type. A new board design or camera setup needs a new memory
  bank and a re-calibrated threshold (lighting shifts scores, see Robustness).
- The F1 threshold is test-set optimistic; use held-out good images in production.
- Only image- and pixel-level AUROC are reported, not region-overlap metrics (PRO).
- PatchCore inference needs a nearest-neighbour search over the memory bank; it is
  slower than the autoencoder, especially on CPU (see the latency column).
- VisA is a research dataset (CC BY-NC-SA 4.0): not for commercial use.

## Tests
```bash
pytest -q
```
Covers data indexing, metrics, evaluation loop, perturbations, input handling
(grayscale/RGBA, corrupt files, tiny/huge images, constant/extreme pixels),
robustness benchmark, inference logic, and both models. GitHub Actions runs the
suite with CPU PyTorch on every push.

## Project structure
```
src/pcbad/
  data.py          dataset indexing, image loading/normalisation
  autoencoder.py   baseline model, training
  patchcore.py     feature extractor, coreset, memory bank, scoring
  metrics.py       AUROC, F1 threshold, per-defect AUROC, latency
  evaluate.py      model-agnostic evaluation loop
  perturb.py       noise / lighting / blur / JPEG perturbations
  robustness.py    robustness benchmark
  inference.py     single-image detection used by the demo
  factory.py       build predictors from checkpoints
  viz.py, report.py, utils.py
scripts/           train_*, evaluate, robustness, update_readme, run_all.sh
app.py             Gradio demo
tests/             unit tests
```
